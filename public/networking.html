Networking fundamentals · 10 topics

Follow the signal from device to device.

Understand the models, addresses, protocols, and everyday technologies that make networks work. Each lesson uses practical examples and a quick check.

Topic 01

What is a network?

A network is a set of devices that exchange data over wired or wireless links. A device creates data, a protocol describes how it is formatted, and the network moves it toward a destination. Network equipment such as switches, access points, routers, and modems have different roles.

Learning objective

Explain that communication depends on agreed protocols and that different devices perform different network jobs.

Takeaway: A network is not one box or one protocol; it is cooperating links, devices, and rules.
Quick check: What does a protocol provide?

Answer: Agreed rules for how devices format, send, receive, and interpret data.

Topic 02

TCP/IP and OSI models

Models organize networking ideas into layers. The TCP/IP model is commonly described with four layers. The OSI reference model uses seven. They are teaching tools: real protocols do not always fit perfectly into one box.

TCP/IP · 4 layers

  1. ApplicationHTTP · DNS · DHCP
  2. TransportTCP · UDP
  3. InternetIP · routing
  4. Network accessWi-Fi · Ethernet

OSI · 7 layers

  1. ApplicationApps
  2. PresentationFormat
  3. SessionSessions
  4. TransportTCP · UDP
  5. NetworkIP
  6. Data LinkFrames
  7. PhysicalSignals

Read top to bottom: application data moves toward the link; the receiving device interprets it in reverse.

TCP/IP layerRelated OSI layer(s)Examples / role
ApplicationApplication, Presentation, SessionHTTP, DNS, DHCP; data used by applications
TransportTransportTCP, UDP; process-to-process delivery and ports
InternetNetworkIP; addressing and routing between networks
Network access / LinkData Link, PhysicalEthernet, Wi-Fi, radio or cable signaling

The OSI layers from top to bottom are Application, Presentation, Session, Transport, Network, Data Link, and Physical. When an app sends data, each layer adds information that helps the next layer deliver it. The receiver interprets those layers in reverse.

Memory aid: TCP/IP groups some OSI responsibilities together. Use the model that helps explain the question at hand.
Quick check: Which model has seven layers?

Answer: The OSI reference model.

Topic 03

IP addresses, MAC addresses, and subnets

An IP address identifies a network interface at the Internet layer so packets can be routed. IPv4 uses 32 bits and is commonly written as four decimal numbers; IPv6 uses 128 bits. A MAC address is a link-layer identifier used on a local link, though its use can be randomized by modern devices.

A subnet groups IP addresses into a network and a host portion. A prefix such as /24 indicates how many leading bits describe the network in CIDR notation. Private address ranges are used inside networks and are not globally routed as public addresses.

Documentation-only example

192.0.2.24/24 uses an address block reserved for examples; it is not a real target.

Takeaway: IP helps route between networks; MAC addresses are used for delivery on a local link.
Quick check: Which address is used for routing between networks?

Answer: An IP address. MAC addressing helps deliver frames on the local link.

Topic 04

Ports and protocols

A port number helps a transport protocol deliver data to the right service or application on a device. TCP and UDP have separate port spaces. A port number alone does not guarantee that a service exists or is reachable.

These are common defaults, not a complete list. Administrators can configure services to use different ports. Learn port roles conceptually and practice only in authorized environments.

Quick check: What does a port help identify?

Answer: The service or application endpoint for data on a device.

Topic 05

Routing, NAT, and gateways

A router forwards packets between networks based on destination IP addresses and routing information. A default gateway is the next hop a device uses when the destination is outside its local subnet. Network address translation (NAT) commonly maps private addresses to a public address at a network boundary.

NAT is not the same thing as a firewall. A firewall applies rules to allow or deny traffic; NAT changes address information as traffic passes between interfaces.

A simplified path: Laptop → Wi-Fi access point → router / gateway → internet service provider → destination network
Takeaway: A gateway moves packets to another network; routing chooses a path.
Quick check: Is NAT itself a firewall?

Answer: No. NAT translates addresses; a firewall enforces traffic rules. A router may provide both features.

Topic 06

HTTP, HTTPS, DNS, and DHCP

HTTP and HTTPS

HTTP is an application protocol for requests and responses, often used by websites. HTTPS is HTTP protected by TLS, which helps provide confidentiality and verify the server identity when certificates are checked correctly. HTTPS does not guarantee that a site is trustworthy or that its content is safe.

DNS

DNS translates names such as example.com into records including IP addresses. A resolver asks DNS servers for information and may cache answers for a time-to-live period.

DHCP

DHCP automatically leases network configuration such as an IP address, subnet mask or prefix, default gateway, and DNS resolver. This makes joining a local network easier than configuring each device manually.

Takeaway: DNS answers “where is this name?”; DHCP helps a device join a network; HTTPS protects web traffic in transit.
Quick check: Which protocol commonly assigns a device its local IP configuration?

Answer: DHCP (Dynamic Host Configuration Protocol).

Topic 07

Wi-Fi

Wi-Fi is a family of wireless local-area networking technologies based on IEEE 802.11 standards. A wireless access point lets devices connect to a local network over radio. Bands, channel use, signal strength, walls, and interference can affect performance.

Modern Wi-Fi security uses WPA2 or WPA3 with strong, unique passphrases. A network name (SSID) identifies a wireless network; it is not a security boundary. Public Wi-Fi should be treated as an untrusted network.

Takeaway: Wi-Fi is the local wireless link; internet access also depends on the router and upstream connection.
Quick check: Does a hidden SSID make a Wi-Fi network secure?

Answer: No. Use modern encryption and a strong passphrase; hiding the name is not a substitute.

Topic 08

Bluetooth

Bluetooth is a short-range wireless technology used for device-to-device connections such as headphones, keyboards, sensors, and file exchange. Bluetooth Low Energy (LE) is designed for lower-power use cases. Profiles define how device types communicate, such as audio or human-interface devices.

Pair only with devices you recognize, keep software updated, and disable discoverability when it is not needed. Bluetooth is not a replacement for Wi-Fi or a general-purpose internet connection.

Takeaway: Bluetooth supports nearby personal-area connections with different profiles and power needs.
Quick check: What does a Bluetooth profile describe?

Answer: How a class of devices uses Bluetooth to exchange information or services.

Topic 09

USB

USB (Universal Serial Bus) is a wired connection standard for data and power between a host and peripherals. USB-C describes a connector shape, not a guarantee of a particular transfer speed or feature. The cable, port, device, and supported USB specification all matter.

USB devices may provide storage, input, audio, networking, or other functions. Treat unknown USB devices as untrusted: they can behave differently from what their shape suggests. Use trusted devices and avoid plugging unknown media into sensitive systems.

Use care: Never assume a USB device is safe because it looks familiar. Follow your organization's device policy.
Quick check: Does USB-C alone tell you the transfer speed?

Answer: No. USB-C is a connector shape; capabilities depend on the devices, cable, and supported standard.

Topic 10

Safe troubleshooting fundamentals

Troubleshoot from the closest layer outward. Check power and link status, confirm the local connection, inspect the assigned IP settings, check DNS, and then consider the application. Change one thing at a time and record what you observe.

  • Confirm the device is connected to the expected network.
  • Check local configuration using built-in network settings.
  • Distinguish a name-resolution issue from an application issue.
  • Use only systems and networks you own or are authorized to troubleshoot.

Commands in the practice terminal show fictional results and never query real hosts. This course does not provide instructions for scanning, exploiting, or bypassing systems.

Takeaway: Observe, form a simple hypothesis, test a permitted change, and document the result.
Quick check: If a name fails but an approved test by IP works, what might you check next?

Answer: DNS configuration and name resolution, while keeping the test within systems you are authorized to use.
