Linux foundations · 11 modules

Get comfortable at the command line.

Learn the ideas behind Linux in small, practical steps. Each module has a short lesson, an example to try, a takeaway, and a quick check.

Module 01

Linux, the kernel, and distributions

Linux is the open-source kernel that manages hardware and lets software communicate with it. A Linux distribution combines that kernel with utilities, an installer, a package manager, and a release process. Ubuntu, Debian, Fedora, and Arch are different distributions built around the same core idea.

Learning objective

Describe the difference between the Linux kernel and a distribution, and identify why distributions package software differently.

Why distributions matter

They differ in release cadence, defaults, support, and package tools. A command may exist on all of them while its installation instructions vary. Check your distribution before following system-level instructions.

# Identify the operating system release, when available cat /etc/os-release
Takeaway: Linux is the kernel; a distribution is a complete operating system built around it.
Quick check: Is Ubuntu a kernel or a distribution?

Answer: A distribution. It includes the Linux kernel plus tools, packages, and a supported release.

Module 02

Terminal and shell basics

A terminal is an application that displays text input and output. A shell reads commands and starts programs. Bash and Zsh are common shells. Commands usually follow this pattern:

command [options] [arguments] # Print the current working directory pwd # Ask ls to include hidden entries and details ls -la
Learning objective

Tell a command, an option, and an argument apart. Try the examples in the simulated practice terminal.

Options change how a command behaves; arguments tell it what to act on. Use --help or a manual page such as man ls to learn more on a real Linux system.

Takeaway: Read the whole command before pressing Enter: command, options, then arguments.
Quick check: In ls -la /home, what is /home?

Answer: The argument: the directory that ls should list.

Module 03

Filesystem and paths

Linux presents files and devices in one directory tree that begins at /, called the root directory. A path is either absolute (starts at /) or relative (starts from your current directory). The special entries . and .. mean “here” and “parent.”

PathCommon purpose
/homePersonal directories for users
/etcSystem-wide configuration files
/varVariable data such as logs and caches
/tmpTemporary files
/usrMany user-space programs and shared resources
pwd cd /home/learner cd ../shared
Takeaway: Start an absolute path at /; interpret a relative path from your current location.
Quick check: What does .. mean in a path?

Answer: The parent directory of the current location.

Module 04

Files and directories

Use commands to navigate, create, inspect, and organize files. These examples are safe to try in this site's virtual filesystem; on a real system, double-check paths before changing or deleting anything.

mkdir practice cd practice touch notes.txt echo "first line" > notes.txt cat notes.txt cp notes.txt copy.txt mv copy.txt archive.txt ls -l

rm removes files. It may not move them to a recycle bin. Learn its behavior in the simulator before using it on a real system. less, head, and tail help inspect longer files.

Takeaway: Understand the target path before copying, moving, or removing a file.
Quick check: Which command makes an empty file?

Answer: touch filename creates an empty file if it does not already exist.

Module 05

Viewing and searching text

Text tools help you inspect output and locate information. grep searches text for a pattern; find searches directories for files by name or other properties. A pipe passes one command's output to another command.

grep "TODO" notes.txt find . -name "*.txt" ls -la | head
Learning objective

Choose a text search when you know what content you want, and a file search when you need to locate a path.

Takeaway: Small tools can be combined; the pipe symbol sends output to the next command.
Quick check: Use grep to find text or files?

Answer: Text. Use find to locate files and directories by path or properties.

Module 06

Users, groups, and permissions

Linux permissions are shown for an owner, a group, and everyone else. The letters r, w, and x mean read, write, and execute. Directories use execute permission to allow traversal.

ls -l report.txt chmod u+x script.sh chmod 640 report.txt

In numeric permissions, read is 4, write is 2, and execute is 1. The digits in 640 describe owner, group, and other permissions respectively. chown changes ownership and usually requires elevated privileges.

Use care: Avoid broad permission changes such as recursively making system files writable. Grant only the access that is needed.
Quick check: What does permission digit 5 mean?

Answer: Read + execute (4 + 1), without write permission.

Module 07

Processes and services

A process is a running program with an ID (PID). ps shows selected processes; top presents a live view. Services are background programs managed by tools such as systemd on many distributions.

ps aux # On systemd-based systems, inspect a service: systemctl status example.service

Stopping a process or service can interrupt work. First identify what it is and why it is running. Service-management commands and permissions vary by system.

Takeaway: Observe first; only stop processes you understand and are authorized to manage.
Quick check: What identifier does a process have?

Answer: A process ID, commonly abbreviated PID.

Module 08

Packages and software

A package manager installs, updates, and removes software while tracking dependencies. Debian and Ubuntu commonly use APT; Fedora uses DNF. Keep commands distribution-specific and read the proposed changes before confirming them.

# Examples for Debian/Ubuntu (not run in this practice site) apt search package-name apt show package-name # Example for Fedora dnf info package-name
Use care: Installing or updating software changes the system. Use your distribution's official repositories and guidance.
Quick check: Why do package-manager commands differ?

Answer: Distributions choose different package formats, tools, and release policies.

Module 09

Storage and disk space

Use df to inspect free space on mounted filesystems and du to estimate the space used by files or directories. A mounted filesystem is attached to a location in the directory tree.

df -h du -sh ~/Documents

Storage layout differs between computers. Don't unmount, format, or delete data from a volume unless you know what it contains and have permission.

Quick check: Which command summarizes free space per filesystem?

Answer: df; the -h option formats values for people to read.

Module 10

Logs and system information

Logs record events that help diagnose issues. Their locations and access rules vary. journalctl reads the systemd journal; tail can show the end of a text file. Avoid sharing logs publicly without checking for personal or sensitive information.

uname -a journalctl -n 30 # For a log file you are permitted to read: tail -n 20 /var/log/example.log
Takeaway: Logs are evidence, not instructions; review their context and protect private data.
Quick check: Which command shows the last lines of a file?

Answer: tail.

Module 11

Environment variables and beginner scripting

Environment variables provide settings to programs. PATH is a list of directories the shell searches for commands. A shell script puts repeatable commands in a file; start with clear inputs, small steps, and comments.

#!/usr/bin/env bash name="learner" printf 'Hello, %s\\n' "$name" # Inspect a variable in your shell echo "$PATH"

Shell behavior and quoting rules matter. Avoid copying scripts you do not understand, and do not run commands as an administrator without a clear reason.

Takeaway: Quote variable expansions when a value may contain spaces, and test small changes first.
Quick check: What is PATH used for?

Answer: It lists directories the shell searches when you enter a command name.
